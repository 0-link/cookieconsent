Parent-controlled serving and smoke scenario

Use an already packed release tarball, never the checkout's dist or source. From the repository root, set TARBALL to its absolute path, then stage outside the repository:

QA=/Users/yarpry/.hermes/cache/scratch/cookieconsent-update/browser-qa
mkdir -p "$QA"
tar -xzf "$TARBALL" -C "$QA"
cp tests/browser/packed-consent.html "$QA/packed-consent.html"
python3 -m http.server 8765 --bind 127.0.0.1 --directory "$QA"

The parent launches/stops that foreground server. Open http://127.0.0.1:8765/packed-consent.html. The only library assets must be /package/dist/cookieconsent.umd.js and /package/dist/cookieconsent.css extracted from the tarball. This fixture is under tests, outside the package's dist/types files allowlist.

  1. Clear QA choice + reload: both counts are zero, consent invalid. Reject optional, open/close Preferences, reload: both counts remain zero, consent valid, only necessary accepted.
  2. Clear QA choice + reload. Check only Analytics, Accept selected: analytics 1, marketing 0. Preferences must show only Analytics selected among optional categories. Close it without saving.
  3. reset(false) + run retains the saved choice and page counts 1/0. Reload: analytics executes once on the new page, marketing stays zero, consent stays valid.
  4. Withdraw optional consent: necessary only, current page counts still 1/0. Reload: both zero and necessary only. Preferences must not reactivate either tracker.
  5. Clear QA choice + reload and repeat with only Marketing: counts 0/1. Accepting the same selection twice must not increment it again. Clear QA choice when finished.

For automation inspect window.qa.snapshot(); wait until its ready is true. No network pixels, fetches, timers, or tracker cookies are used. CSP blocks network connections and images.
